# Проект: ИИ-агент «Анализ организационной структуры и функционала»

## Задача
Агент сравнивает комплекты документов «до» и «после» реорганизации (оргструктуры, положения
о подразделениях, должностные инструкции, приказы; форматы Word, PDF, Excel), определяет
созданные / сохранённые / реорганизованные / упразднённые подразделения, сопоставляет функции,
выявляет потерю функций, дублирование и конфликт интересов и формирует объяснимое заключение.
КАЖДЫЙ вывод подтверждается ссылкой: документ + пункт + дословная цитата.
Агент НЕ делает утверждений, которых нет в документах. Выводы — рекомендательные.

## Must have (из ТЗ)
1. Какие подразделения реорганизованы, сохранены, созданы (по документам).
2. Сопоставление функций «до/после», выявление потери функций.
3. Сопоставление функций между подразделениями: дублирование и конфликт интересов.
4. Для каждого вывода — источник: документ и пункт/фрагмент.
5. Итоговое аналитическое заключение, понятное пользователю.

## Архитектура (шаги агента)
1. **parse** — docx/pdf/xlsx/txt → текст → фрагменты по номерам пунктов (`2.4.7.`, `3.4.`,
   в т.ч. номера посреди строки вида `3.10.Текст`). Фрагмент: doc, clause, text, section.
2. **structure** — подразделения, аббревиатуры, подчинённость (regex + LLM со строгим JSON).
   Сравнение: created / kept / reorganized / removed + доказательства.
3. **functions** — извлечение функций: unit, function (краткая формулировка), clause, quote.
4. **match** — сопоставление функций «до/после»: эмбеддинги (OpenAI text-embedding-3-small),
   без ключа — TF-IDF; спорные пары подтверждает LLM. Нет пары → кандидат на ПОТЕРЮ.
5. **findings** — дублирование (похожие функции у разных подразделений «после»),
   конфликт интересов (функции против запретов, напр. п. 5.8 Положения: участие в процессах,
   внедрение контролей, согласование операций; совмещение выполнения и контроля).
6. **verify** — каждая цитата ищется в исходном тексте (нормализация + нечёткое совпадение ≥ 90).
   Не нашлась → вывод помечается «не подтверждён» и не попадает в заключение.
7. **report** — заключение только из подтверждённых выводов + рекомендации; экспорт DOCX/XLSX.

## Контракт
```python
# src/pipeline.py (Бекарыс)
def run(before: list[Path], after: list[Path], use_llm: bool = True, log=None) -> dict:
    """{
      "units":    [{"name","abbr","status","evidence":[Evidence]}],
      "function_map": [{"before_unit","before_function","after_unit","after_function",
                        "status": "kept|moved|changed|lost|new", "similarity", "evidence":[Evidence]}],
      "findings": [{"id","type":"loss|duplicate|conflict|reorganization","severity":"high|medium|low",
                    "title","description","units":[str],"evidence":[Evidence]}],
      "conclusion": str
    }
    Evidence = {"doc","clause","quote","verified": bool}"""
```
`log` — функция `log(step, status, message)` для журнала агента в интерфейсе.

## Демо-режим
Без ключа: TF-IDF вместо эмбеддингов, regex вместо LLM, а для `data/sample` — готовый результат
из `artifacts/sample_result.json` (генерируется `scripts/build_sample.py` с ключом).

## Контрольный набор (проверка из ТЗ)
`data/control/` — копия «после» с известными изменениями: удалена функция, функция продублирована
в другом подразделении, подразделение переименовано/объединено. `data/control/expected.json` —
ожидаемые находки. `python scripts/eval_control.py` печатает, что найдено и с какими источниками.

## Правила
1. Ни одного вывода без Evidence. Формулировки — «признаки», «кандидат», «требует проверки».
2. Не хардкодить названия подразделений и ответы под тестовые документы.
3. Проект работает без GPU и без ключей. Ключи только через `src/config.py`; `.env` не читать и не коммитить.
4. LLM-вызовы в try/except с запасной логикой. Ответы LLM — строгий JSON, валидировать.
5. Новые библиотеки и сервисы — в README («Данные и внешние сервисы»).
6. После изменений: `pytest -q`.
